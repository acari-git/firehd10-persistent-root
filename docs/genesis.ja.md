# Genesis：ユーザーごとの鍵と最初の READY

> English: [genesis.md](genesis.md)

本システムの信頼の錨は、インストールごとの ECDSA キーペアである。
共有の「リリース」鍵は存在しない：他人のピン留め鍵でビルドされた APK は、
構造上、あなたの端末で証明を完了させることが決してできない。

## genesis が存在する理由

通常の完了は、証明を INFLIGHT ジャーナルレコードに結び付ける。最初の
READY レコードには結び付ける対象が何もないため、それは別個の、
ドメイン分離された **genesis 証明**（`stage4-genesis-v1|…`）によって
作られ、同じピン留め鍵に対して `Stage4GenesisVerifier` が検証する。
genesis には生きている root セッションと操作者トークンが必要であり、
無人サイクルが自力でできることではないよう、意図的にそう設計されている。

## フロー（genesis セッション、2026-11-01 に実行されたとおり）

1. **端末内でキーペアを生成する**。root セッションの中で：秘密鍵は
   保管場所へ直接書かれる。`/data/snusnu_root/signer/proof-key.der`
   （ディレクトリ `root:root 0700`、ファイル `0400`）。端末の外へ
   コピーされることは決してない。離れるのは公開の半分だけで、操作者が
   運ぶ DER ファイルとしてである。
2. **APK を再ビルドして公開鍵をピン留めする**：
   `app/build-v2.sh <device-public.der> "<device label>"` が DER から
   `Stage4PinnedProofKey.java` を再生成し、再ビルドする。ステージされた
   デフォルトがピン留めするのは、ラベルされた **ホストテスト鍵** であり、
   その秘密の半分は、それを作ったセッションで削除された — デフォルトの
   ピンでビルドされた APK は、意図的に、どこでも有効なものに署名しない。
3. **署名者の report モードを実行する**。そして、いかなる署名よりも前に、
   すべての自己検証ゲート（コンテキスト、保管、Enforcing）の合格を
   要求する。
4. **操作者トークンを置く**：内容が *現在のブート id* である、root 所有の
   `0400` トークンファイル。他のブートを名指しするトークン、あるいは
   消費済みのトークンは拒否される。
5. **genesis に署名する**：署名者はジャーナルの保留中チャレンジに対する
   genesis 証明を生成し、proof-drop メールボックスを通じて届け、
   ドロップへアプリの SELinux ラベルをコピーする。
6. **アプリを再トリガーする**（再ビルドした APK の `pm install -r`）。
   アプリは genesis 証明を検証し、`READY:<boot>:<count>` を書き、
   `proof_status=genesis_installed` を設定する。

genesis の後、次の武装ブートは無人サイクルを走らせることができ、
検証された通常の完了のたびに、次が再武装される。

## ロックアウト復旧は同じ経路

`beginOneShot` の後にブートが失敗すると、ジャーナルは INFLIGHT に
張り付き、アプリはそれ以上のことを正しく拒否する。復旧：

1. ホストドライバで一時 root を再取得する（確率的。
   `failure-modes.ja.md` を参照）。
2. 端末上でジャーナル、ガード、保留中のチャレンジを読む。
3. 署名者 report → トークン（現在のブート id）→ `sign-genesis
   <challenge>` → ドロップ → `pm install -r`。
4. ジャーナルは `genesis_installed` とともに READY に戻る。Magisk を
   再配置し、Enforcing を復帰させ、ハッシュスイープを実行し、無効化した
   状態でキャッシュ sentinel を再インストールし、それから再武装する
   （sentinel を保持場所へ、persist フラグをオンに、落ち着かせ、
   読み戻す）。

この正確なフローが、ブート209の失敗の後、2026-11-02/03 に受入端末を
復旧させ、システムはその後、残りの受入ブートを無人で完了した。

## 保管ルール（これらを弱めないこと）

- 秘密鍵は **端末内で** 生成する。他所で生成された鍵を決してインポート
  せず、端末の鍵を決してエクスポートしない。
- 端末上の保管場所は正確に1つ。散らかった2つ目のコピーは、利便性では
  なく、発見事項である。
- genesis／復旧による完了は決して再武装しない。武装は、通常の検証された
  完了によってのみ得られる。
