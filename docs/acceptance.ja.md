# 受入の証跡

> English: [acceptance.md](acceptance.md)

開発端末（Fire HD 10、trona/KFTRWI、Fire OS 7.3.3.1、フィンガープリント
`Amazon/trona/trona:9/PS7331.4463N/0031575863040`）で、2026年11月に
測定。生のセッション証跡は公開されていない。これは記録の要約である。

## 実測の信頼性

| 経路 | 結果 | 備考 |
|---|---|---|
| ホスト駆動の再取得（ドライバ Phase B） | 新規ブートごとに **9/19 ≈ 47%** | ミスは `ENODATA_LEAK_MISS_NO_WRITE`：カーネル書き込みなし、端末は素の状態に戻る。 |
| アプリ側の無人サイクル（武装ブート） | **9/10** | ブート203–208、224、225、226 が完了。ブート209はミスし（failure-modes 参照）、フェイルクローズで武装解除した。 |
| 署名者の自動完了の測定（ブート204） | フルサイクル約93秒 | 再起動 → ジャーナル READY、`adb reboot` の後の操作者入力はゼロ。 |
| 冷起動サイクル（ブート225） | 約90秒 | 電源断からの冷起動でも同じ形。 |

## 受入シーケンス：5/5 PASS

常設の有効化は 2026-11-02 にオンにされ、正式シーケンスは再武装クロージャ
ビルドに対して実行された（APK SHA-256 `88e09d7a…`、署名証明書
`063dc4aa…`）：

| # | ブート | 種別 | 結果 |
|---|---|---|---|
| 1 | 206 | 通常再起動 | PASS — 完全な無人サイクル、persist ライフサイクル 1→0→1 を測定 |
| 2 | 207 | 通常再起動 | PASS |
| 3 | 208 | 通常再起動 | PASS |
| — | 209 | 電源断 #1 → 電源投入 | **FAIL** — キャリアの試行1で ENODATA ミス。アプリは設計どおり正確にフェイルクローズで武装解除した（persist 1→0、再武装なし、損傷なし） |
| — | 210–223 | 復旧 | ドライバ再取得（ENODATA の3連続ミスの後、成功）、ジャーナルの読み取り、sign-genesis ロックアウト復旧、Magisk 再配置、ハッシュスイープ 10/10、sentinel 再インストール、再武装 |
| — | 224 | ウォーム再起動（追加） | PASS — 復旧したシステムでの完全な無人サイクル（5件には数えない） |
| 4 | 225 | 冷起動 #1（電源断 → 電源投入） | PASS — すべての基準を2回検証 |
| 5 | 226 | 冷起動 #2 | PASS — すべての基準を2回検証 |

ブートごとの PASS 基準：ジャーナル `READY:<boot id>:<count>`、
`proof_status=proof_completed_dps`、`rearm_status=rearmed_on_proof`、
persist ライフサイクル 1→0→1、`getenforce=Enforcing`、`su -c id` =
`uid=0`、`u:r:magisk:s0`、同じブートに結び付いたブートごとの witness を
伴う起動結果 OK。

併せて測定されたこと：タブレットは USB 給電で **自動ブートしない**。
したがって冷起動には物理的な電源ボタンの押下が必要であり、2件の冷起動
受入項目はブート回数ではなくブートの種別によって定義される。

## プロジェクトのゲート台帳（SAFE_ROOT_GOAL、Step 3 判定）

開発プロジェクトは11の文書ゲートを追跡した。締めくくり時点の最終判定：

| ゲート | 結果 |
|---|---|
| G01 端末の同定 | pass |
| G02 署名付きアンロック／同等物 | **blocked** — trona に正規のアンロックは存在しない。納品された永続化は意図的にそれなしで動作する（ブートローダーはロックされたまま） |
| G03 バックアップ／復元 | partial — 本物の災害復旧インポートは実施せず |
| G04 Recovery ロールバック | partial — 本物の Recovery でのエンドツーエンド復元は実施せず |
| G05 管理下で利用可能な `su` | pass |
| G06 システム全体の Enforcing ＋ ドメイン監査 | pass（Magisk ドメインの広さは監査で開示） |
| G07 通常再起動3回 | pass（206/207/208） |
| G08 冷起動2回 | pass（225/226） |
| G09 1つのプロトコルとしての機能＋48時間安定性 | partial |
| G10 最小権限／孤児サービスなし | partial — 孤児サービス側は証明済み（リッスンするのは設計された 4321 ゲートのみ。4325 は一時的）。最小権限側は完全には最小化されていない（WRITE_SECURE_SETTINGS、システム UID ゲートは設計上残る） |
| G11 OTA ＋ 復旧計画の証明 | not_verified — 本物の OTA とエンドツーエンドの素への復旧は、実機では意図的に実施せず |

プロジェクトの `goal_status` ツールは、文書ゲート 5/11 の合格と、
いずれかのゲートが未達である間は *構造上* NO_GO となる全体判定を
報告する。残る6項目は、別途の承認を必要とする保証ゲートであり —
いくつかは実機で意図的に避けられた操作である — 納品されたシステムの
欠陥ではない。

締めくくり後の最終の定常状態：端末オン、Enforcing、persist 武装済み、
ジャーナル READY、MagiskSU 稼働 — システムは通常再起動3回＋冷起動
2回にわたって、すべて完全無人で証明された。
